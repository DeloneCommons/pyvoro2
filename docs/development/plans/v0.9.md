## Intended outcome

v0.9.0 should be the first release whose existing forward, periodic, and
separator-inverse core can seriously be treated as a candidate for the public
semantics of 1.0.

The release should leave pyvoro2 with:

- coherent mathematical-weight and explicit-radius input semantics across
  `compute()`, `locate()`, and `ghost_cells()`;
- periodic user-lattice semantics that are distinct from the Voro++ backend
  representation and that accept valid left- and right-handed bases without
  reordering user lattice vectors;
- representation-robust certified nearest/minimum-image and duplicate-safety
  geometry for supported periodic domains, including deliberately poor but
  equivalent lattice representations within explicit structural resource
  limits;
- certified periodic face/edge and ghost image metadata whose correctness no
  longer depends on a user-selected finite search window;
- native certificate qualification based, wherever the accepted proof permits,
  on exact source closure and measured build/floating-point execution properties
  rather than one exact compiler version as the semantic correctness criterion;
  compiler family/version remains reproducibility provenance, and an exact-version
  restriction remains possible if a proof-relevant dependency is demonstrated;
- all public periodic integer shifts interpretable in the user-supplied lattice
  basis with one documented sign convention;
- a normal supported realization-aware separator workflow whose stable result
  contract remains distinct from the empirical convergence properties of its
  outer active-set refinement;
- separator mismatch, hard-constraint, and soft-penalty measurement spaces that
  can be selected independently without introducing the future generic mixed
  observation-block architecture;
- public-workflow qualification that uses only supported APIs and tests
  user-visible invariants rather than implementation details;
- a final pre-1.0 API/lifecycle audit that removes known compatibility artifacts
  rather than carrying them into the v0.9.x downstream soak period.

After Checkpoint C and before Phase D/WP12, the maintainer rereads the complete
codebase for comprehension and architecture reconciliation, followed by a
separate architectural/technical audit and explicit disposition of findings.
Accepted pre-release remediation, if any, receives its own tests/qualification
before WP12; WP12 qualifies the resulting public workflows rather than a tree
already scheduled for immediate reconsideration. WP13 follows WP12. A bounded
review of changes since that recovery baseline then precedes documentation,
with maintainer escalation to full review when the delta/evidence warrants it.
The documentation overhaul remains before #48 frozen-source qualification.

The released v0.9.x series is then the downstream-readiness/soak phase. v0.9.0
must remove known critical semantic and API holes, but it is not required to
prove that real downstream use can never discover another issue. v1.0 is gated
on that soak showing that the existing forward, periodic, and separator-inverse
core has no remaining critical correctness or API gap requiring another known
incompatible redesign.

## Baseline and motivation

The reviewed v0.8.0 source already contains substantial stabilization work that
should be reused rather than redesigned:

- `compute(..., mode="power")` already accepts mathematical `weights=` and
  converts them to the Voro++ radius representation with one common gauge;
- ADR 0012 and `pyvoro2._internal.periodic_images` already provide certified
  nearest/minimum-image geometry whose successful result does not depend on a
  finite user search cube;
- ADR 0013 centralizes generator preparation and mandatory backend-safety
  duplicate checks;
- ADRs 0014 and 0015 already define separator observation/source identity and
  atomic realization-aware final-state semantics;
- the active-set implementation already keeps outer termination separate from
  the final inner-fit status and represents cycles, iteration limits,
  infeasibility, and numerical failure structurally;
- the existing examples and integration tests already provide a qualification
  scaffold that can be extended instead of replaced.

The remaining pre-1.0 problems are concentrated rather than package-wide.

`locate()` and `ghost_cells()` still lack weight-first parity. `PeriodicCell`
currently conflates mathematical validity with orientation/conditioning choices
that belong to backend or proof machinery. Public user-cell fractional geometry
is not separated cleanly from Voro++-primary remapping. Certified nearest-image
search can become impractical for a very poor equivalent lattice basis, and the
same representation sensitivity can reach mandatory periodic duplicate safety.
Periodic face/edge image reconstruction still depends on finite search-window
machinery. Periodic ghost cells expose an additional correctness problem:
native neighbor integers do not reliably distinguish persistent generators,
periodic images of the temporary ghost itself, and walls.

The separator inverse architecture is already much closer to the intended 1.0
shape. The main remaining semantic issue is that the observation measurement
space currently also controls mismatch, hard bounds, and scalar penalties even
though these are independent scientific choices. The ordinary
realization-aware workflow also still reaches an advanced/experimental-level
surface even though its result and termination model is already largely
stabilized.

This plan therefore prioritizes coherent periodic foundations first, then
periodic boundary/metadata semantics, then the smaller inverse stabilization
workstream, followed by public-workflow qualification and a final API audit.

## Accepted maintainer decisions

The following eight decisions are settled for this plan. WP0 records durable
parts in ADRs and the target API inventory before production implementation
relies on them.

### D1 — Exact periodic ties are selected in physical space

When several periodic images are exactly tied, candidate selection uses the
exact Cartesian displacement rather than integer coefficients in the supplied
lattice basis. In fixed caller Cartesian axes, orientation `+1` selects the
lexicographically smallest exact displacement tuple and orientation `-1` the
largest. The selected physical image is then expressed in the user's basis.

This total order is exact, invariant under an exact unimodular change of lattice
basis, antisymmetric under pair reversal, and covariant when either endpoint is
translated by a lattice vector. It deliberately changes the ADR 0012
coefficient-space rule. The contract does not claim invariance under an
arbitrary global rotation: choosing one deterministic member of a rotationally
symmetric exact tie necessarily uses a reference convention.

### D2 — `PeriodicCell` mathematical validity is separate from representation quality

A periodic lattice is mathematically valid when its finite binary64 basis is
non-degenerate; a negative determinant denotes a left-handed basis rather than
an invalid one. Poor conditioning can produce a warning, an operation-level
backend-representability failure, or a certified-geometry resource failure, but
must not by itself be conflated with mathematical invalidity.

Because this admits poorly conditioned but exact non-degenerate bases, the
integer shift for deterministic half-open user wrapping must be decided from
the exact dyadic basis, origin, and input point. A rounded inverse followed by
`floor`, epsilon snapping, or nearest-integer repair is not the authority for
the half-open cell decision. Returned binary64 coordinates are validated rounded
views of that exact decision. WP2 must define the visible boundary convention for
an exact remainder that rounds to an upper endpoint: rounding must not silently
change the exact wrap shift, and the float view must satisfy a documented
reconstruction envelope rather than an epsilon-selected cell decision.

### D3 — Ghost boundary identity uses an explicit data contract

Periodic ghost boundaries must distinguish conceptually among:

- a persistent generator image;
- another periodic image of the temporary ghost itself;
- a non-periodic wall.

Native positive/negative integer neighbor values are not the semantic authority
for this distinction. The internal/public contract is a tagged record whose
kind and payload fields are validated together. A representative conceptual
shape is:

```text
BoundaryReference
    kind: generator | ghost_self | wall
    generator_id: int | None
    shift: integer tuple | None
    wall_id: int | None
```

The exact public spelling is fixed during WP0/API-inventory work rather than by
this example. The semantic invariants are:

| Kind | Generator ID | User-basis shift | Wall ID |
|---|---|---|---|
| persistent generator | required | required where periodic image identity applies | none |
| ghost self-image | none | required and non-zero | none |
| wall | none | none | required where the existing domain exposes wall identity |

Existing ordinary `compute()` adjacency fields need not be broken merely for
schema symmetry, but internal consumers must stop treating integer sign alone
as boundary kind. The ghost API must not expose an undefined native integer as
an owner identifier.

A tagged ghost boundary record requires qualified semantic evidence. The
closed [WP7 decision](../decisions/0023-wp7-certified-ghost-boundaries.md)
requires N source attribution plus exact public-semantic S positivity and
coverage for positive references, retains proved internally collapsed raw
occurrences with `boundary_reference=None`, and requires hard atomic failures
when attribution or eligibility cannot be established. Ordinary
persistent 3D faces instead follow the closed
[WP5 contract](../decisions/0021-wp5-native-occurrence-and-exact-face-certification.md):
unique native image attribution is required to return requested shifts;
unresolved attribution fails atomically. Exact E/S zero, absent, coverage and
reciprocity findings belong to the requested consistency diagnostic and follow
`tessellation_check`, without silently removing native faces. Planar and
ghost output/normalization policy is fixed by their owning work packages.

Candidate assignments may be deduplicated as physically equivalent only when
they define the same exact cut and the same public semantic provenance
(`kind`, owner, and user-basis shift). Different owners, shifts, or boundary
kinds are not made equivalent merely by similar residuals; they require trusted
disambiguating evidence or a structured ambiguity/multiplicity result.

### D4 — Obsolete face/edge reconstruction controls are removed immediately

After certified boundary-image reconstruction lands, correctness-critical
public knobs that no longer have a scientific meaning are removed rather than
carried through a deprecation cycle. This includes the applicable
face/edge-shift search, validation, repair, and reconstruction-matching tolerance
arguments.

Separator `image_search` is different and remains a correctness-neutral
performance seed under ADR 0012. General tessellation diagnostic tolerances are
also separate and are not removed merely because they are tolerances.

### D5 — Ghost power representation gets the final names immediately

`ghost_cells()` supports two complete power-representation families:

```python
weights=..., ghost_weights=...
```

or:

```python
radii=..., ghost_radii=...
```

Mixed weight/radius families are rejected. The old `ghost_radius` spelling is
removed directly; no deprecated alias is carried through v0.9.

For mathematical weights, persistent generator weights and all temporary ghost
weights in one call share one common weight-to-radius gauge conversion.

### D6 — Separator measurement axes are independent

The space in which an observation target was supplied is distinct from the
space used by:

- mismatch/objective evaluation;
- hard feasibility constraints;
- each scalar soft penalty.

`SeparatorObservations.measurement` continues to describe the observation
source/target space. Model terms gain their own optional space, and an omitted
term space inherits the observation space so existing same-space models retain
their meaning.

The post-Checkpoint-B Phase C entry gate #104 accepted a bounded row-bound
extension of selected existing separator values/applicability. Measurement
spaces remain term-global. WP10 therefore combines this measurement-space
separation with A+B row-bound policy: selected hard values/applicability and
selected penalty interval/strength values may be scalar or length-m row policy
that is bound and projected with the ordered observations.

This does not introduce per-row spaces, arbitrary callbacks/loss dispatch,
generic mixed observation blocks, site anchors, topology constraints,
prescribed measures, chemistry-specific types, or another inverse family.
The completed mandatory late-Phase-C refinement gate below retains all five
robust/shape parameters scalar/term-global. No C refinement is required for
Checkpoint C; three meaningful candidates remain explicitly deferred.

### D7 — Realization-aware fitting has a distinct supported high-level function

The fixed-observation separator solve and empirical realization-aware outer
refinement remain visibly different algorithms. Ordinary realization-aware use
moves under `pyvoro2.inverse` through a separate supported high-level function
rather than a mode flag on `fit_weights_from_separators()`.

The current active engine and `SelfConsistentPowerFitResult` should be reused.
Advanced path/hysteresis controls can remain in the advanced separator
namespace without becoming 1.0 commitments.

### D8 — Public point-centered/symmetric-bound convenience is not a v0.9 gate

The measurement-space redesign should make point-centered or symmetric bounds
straightforward internally, but v0.9 does not add a public convenience type or
syntax unless implementation exposes a concrete need that receives a separate
maintainer decision.

between two policy families from evidence rather than from an abstract fork
rule:

- an **upstream-functional-source policy**, under which pyvoro2 carries no
  pyvoro2-specific functional Voro++ source changes; or
- a **bounded downstream-patchset policy**, under which narrow, explicit,
  isolated, regression-tested Voro++ patches may be maintained when required by

The temporary-versus-permanent lifetime of a patch is therefore evidence about
maintenance cost, not the definition of a functional fork. A proposed change
that materially alters Voro++ geometry algorithms, numerical behavior, or core
backend architecture remains a separate maintainer-level architecture decision
rather than being authorized implicitly by the bounded-patchset option.

## Core periodic architecture

The periodic workstream uses three conceptually separate layers. The
implementation may share storage or helpers where appropriate, but public and
proof semantics must not collapse these layers again.

### User lattice layer

Let the user-supplied lattice vectors be rows of `A` and let `o` be the origin.
Public user-cell geometry follows

```text
x = o + f @ A
```

where `f` is a fractional row vector.

This layer owns:

- Cartesian-to-fractional conversion;
- fractional-to-Cartesian conversion;
- fractional wrapping modulo the integer lattice;
- Cartesian wrapping into the user parallelepiped;
- user-basis integer shifts;
- public reconstruction equations and shift signs;
- the handedness of the user-supplied basis.

All public periodic integer shifts must ultimately be interpretable in this
basis.

### Backend periodic-frame layer

Voro++ uses a lower-triangular periodic representation. The preferred design to
verify and implement is a centralized sign-normalized orthogonal factorization,
for example through QR of the transpose,

```text
A.T = Q @ R
L = R.T = A @ Q
x_backend = (x - o) @ Q
x = o + x_backend @ Q.T
```

with coordinated sign normalization of columns of `Q` and rows of `R` so the
lower-triangular backend matrix `L` has positive diagonal entries.

For a right-handed user basis, `Q` is a proper rotation; for a left-handed
basis it may be an improper orthogonal transformation/reflection. This changes
the internal frame without permuting user lattice vectors or changing integer
coefficient semantics.

This layer owns:

- Cartesian/internal transformations;
- Voro++ lower-triangular parameters;
- Voro++ primary-domain remapping;
- backend-used generator/query coordinates;
- transformation of native geometry back to Cartesian coordinates.

Existing `remap_cart()` and `remap_internal()` retain their Voro++-primary
meaning. New user-parallelepiped operations must receive distinct names.

An improper transformation can reverse orientation. WP2 must therefore audit
ordered face-vertex cycles, normals, and any signed-orientation assumptions
rather than assuming that distances and unsigned measures are the only affected
quantities.

### Periodic coordinate vocabulary

Periodic query and generator paths distinguish four concepts even when an
implementation can share storage:

- original input Cartesian coordinates;
- user-parallelepiped wrapped coordinates plus the exact user-basis wrap shift;
- backend-primary/cell-site Cartesian coordinates plus any backend remap shift;
- native internal-frame coordinates.

`p_ghost_site` means the active cell-site representative that anchors returned
ghost geometry. It is never the original unwrapped query. If implementation
reanchors geometry before packaging, every associated image shift must be
transformed consistently and the result must still satisfy its documented
reconstruction equation.

### Exact lattice-arithmetic layer

Finite binary64 lattice components, origins, and exact user inputs are
interpreted as dyadic rationals where they control a discrete decision. This
layer owns:

- exact determinant/non-singularity and determinant sign;
- exact fractional solve/floor decisions for user half-open wrapping;
- exact user-basis wrapping shifts and their reconstruction checks;
- WP4 certified unique integer-translation recovery for approximate native
  Cartesian image positions within an explicitly justified exact compatibility box;
- exact proof data used by certified periodic geometry;
- private exact unimodular basis reduction;
- exact mappings between reduced-basis and user-basis shifts;
- proof-complete integer candidate enumeration;
- representation-invariant exact tie comparison;
- structural work/resource accounting.

For a private reduced row basis

```text
A_reduced = U @ A
```

where `U` is an exact integer unimodular matrix, shift mappings are

```text
s_user = s_reduced @ U
s_reduced = s_user @ U_inverse
```

using exact integer arithmetic. Python integers are used internally; the
existing public signed-int64 shift range is checked only when a public shift is
materialized.

The exact determinant, fractional solve/floor, and integer-translation
primitives are foundational and may be introduced in WP2. WP3 extends the same
private layer with unimodular reduction; it does not own the first exact
operation merely because reduction is its main feature.

The private reducer is selected for the computational goal of certified
closest-vector/minimum-image and related lattice enumeration. Crystallographic
canonicalization is not the goal, so Niggli reduction is not assumed to be the
right strategy.

### Boundary-certification numerical authority

For ordinary persistent 3D faces, the closed
[WP5 G0 contract](../decisions/0021-wp5-native-occurrence-and-exact-face-certification.md)
replaces the earlier generic returned-geometry envelope proposal. Actual
native support/topology N is observed and attributed by complete
source-compatible binary64 image construction. When diagnostics are requested,
two separate complete exact ideals are reconstructed: E from witnessed native
sites/lattice/backend radii, and S from caller sites/lattice/public weights. Both
must be positive for a successful exact-consistency audit; disagreement is a
structured representation-conflict diagnostic. A uniquely attributed native
shift remains available regardless of that audit result. N, E and S are not
interchangeable. WP6/WP7
must qualify their distinct native routes.

Generic approximate-native translation consumers such as WP4 require unique
compatibility within their explicitly justified exact region. Ordinary WP5 3D
faces instead require a unique source-compatible image/provenance class under
ADR 0021's complete producer construction before E/S ideal classification.
Inverting approximate native bits alone proves neither result; ambiguity is a
structured failure, never a nearest-residual guess.

### Qualified representation-robustness claim

v0.9 does not automatically run Voro++ on the privately reduced equivalent
basis. Consequently the release makes two deliberately different claims:

1. pyvoro2's certified lattice geometry should remain practical for
   substantially poorer equivalent representations, subject only to explicit
   private structural resource limits;
2. end-to-end tessellation is qualified on deliberately poor but still
   backend-resolvable equivalent bases, not on arbitrary extreme unimodular
   shears that Voro++ itself may fail to represent or resolve reliably.

A mathematically valid cell can therefore construct successfully and later
produce a clear backend-representability or certified-resource failure. This is
preferable to calling the lattice itself invalid.

### WP3 — Add exact private lattice-basis reduction and shift mappings

**Purpose**

Provide one reusable private exact reduction primitive for proof-oriented
periodic geometry rather than burying an ad hoc reducer inside one caller.

**Main code areas**

- the shared private exact lattice-arithmetic/reduction module introduced or
  contracted by WP2;
- exact dyadic helpers currently owned by periodic-image code;
- private caching/resource policy;
- adversarial representation fixtures and test-only oracles.

**Required contract**

For `A_reduced = U @ A`:

- `U` and `U_inverse` are exact integer matrices;
- `det(U) = +/-1`;
- the equality and inverse relationship are verified exactly;
- reduced/user integer shifts round-trip exactly;
- no public reduction API is exported;
- Voro++ continues to use the normal backend frame, not the reduced proof basis.

**Selected strategy**

Issue [#56](https://github.com/DeloneCommons/pyvoro2/issues/56) fixes
deterministic exact rank-3 LLL with `delta = 3/4`, exact half ties toward zero,
strict Lovasz swaps, and only the prescribed final row-sign normalization.
Planning compared the strategy against the computational objective that matters
here:

- proof-derived coefficient-box/candidate count;
- maximum coefficient growth;
- exact integer bit growth;
- deterministic termination;
- behavior under adversarial unimodular shears.

A crystallographic canonicalizer such as Niggli reduction is not the goal.
Pairwise reduction misses three-vector cancellations, while stronger LLL,
Minkowski/Selling-like strengthening, or local search did not provide enough
measured proof-work advantage to justify additional production selection and
certification obligations. Changing the selected policy requires a new review;
WP3 does not carry a production comparison framework.

**Acceptance criteria**

- WP2 exact determinant/wrap primitives are reused and extended rather than
  duplicated;
- finite binary64 basis components are represented exactly as aligned dyadics;
- exact transform/mapping invariants pass across deterministic and randomized
  unimodular fixtures;
- structural resource limits are explicit private limits on proof work and
  never authorize an incomplete/heuristic answer;
- exceeding such a limit yields a structured resource failure;
- the chosen reducer materially reduces proof workload on the repository's poor
  representation fixtures and additional large-shear cases;
- a short correctness note, independent exact oracles, and an analytically
  bounded test-only workload evaluator exist before the production
  implementation is accepted.

**Stop condition**

If no evaluated exact strategy gives useful workload reduction with tractable
mapping/termination semantics, stop for architecture review. Do not replace the
requirement with a hidden finite search radius.

### WP7 — Define ghost boundary identity and certify periodic ghost shifts

**Purpose**

**Main code areas**

**Required behavior**

exact public-semantic S cell. Source association identifies boundary kind,
owner and native image before S determines positive-reference eligibility and
coverage. The [closed WP7 ADR](../decisions/0023-wp7-certified-ghost-boundaries.md)
fixes collapsed raw occurrences, empty dispositions and hard failure actions;
the ordinary WP5/WP6 audit actions do not apply. Native neighbor integers are
not the public semantic source.

`p_ghost_site` is the actual stored ghost's materialized Cartesian representative
that anchors the returned ghost geometry. It is never the original unwrapped
query. Generator shifts in this chart are `sigma-K_j`, with `K_j` the sum of
preparation and actual insertion translations; ghost self shifts are nonzero
`sigma`. This differs from ordinary persistent source-centered transport.

For a ghost self-image:

```text
p_image = p_ghost_site + shift @ A
shift != 0
```

For a persistent generator boundary:

```text
p_image = p_generator_original + shift @ A
```

For a wall, no periodic image shift is present.

Source inspection establishes that the 3D temporary ID is uninitialized in
all four legacy binding routes. Periodic revisits or triclinic image copies
can read it before Python normalization; the strictly nonperiodic rectangular
route is a negative control for that particular read. WP7 therefore requires
initialized selected-cell execution of a per-query augmented population and
verification of actual insertion before any possible ID read/copy. The
internal temporary ID is not public semantic authority.

WP7 should prefer a clean binding-only correction when it satisfies the contract
without fragile reconstruction or undocumented backend assumptions. If that is
not sufficient, the issue must reduce the required vendored Voro++ change to a
minimum concrete diff and trigger D9 before the source patch is accepted. WP7
must not assume in advance that such a patch has to be temporary or accepted
upstream; those are policy consequences to decide from the concrete change, not
preconditions for establishing the minimum correct native solution.

**Acceptance criteria**

- empty persistent periodic container plus one ghost is covered where the
  backend supports the operation;
- one- and multiple-persistent-generator periodic systems are covered;
- standard and power modes are covered;
- 2D and 3D are covered;
- supported partial-periodic wall cases remain distinguishable from ghost
  self-images;
- ghost self boundaries have explicit `ghost_self` semantics and non-zero
  user-basis shifts;
- persistent-neighbor boundaries have stable generator IDs and user-basis
  shifts;
- no uninitialized 3D ghost neighbor value is read in any of the four

- 2D empty/sparse cases cover native negative codes and non-semantic collapsed

### WP10 — Decouple separator spaces and add bounded row-bound model policy

**Status:** implemented, independently accepted and squash-merged through
#107 / PR #108 as `0cf97de42065b35be914190a071967948fc90837`.

**Purpose**

Implement independent observation/mismatch/hard/penalty measurement spaces and
the bounded A+B row-policy architecture accepted by #104, while preserving the
existing fixed-separator mathematical family.

**Main code areas**

- separator constraints and model terms;
- problem construction and row-policy binding;
- hard-constraint/coupling compilation;
- objective/proximal/direct/ADMM paths and their caches;
- component and active-set repeated subsetting/final refit;
- result/resolved-policy views and report schema v2;
- observation identity and numerical regression tests.

**Required public model**

Mismatch terms, hard constraints, and scalar boundary penalties can each select
`fraction` or `position` independently. An omitted term space inherits
`SeparatorObservations.measurement`. Space selection remains term-global.

The accepted scalar-or-length-m row whitelist is:

```text
Interval:                    lower, upper, applicable
FixedValue:                  value, applicable
SoftIntervalPenalty:         lower, upper, strength
ExponentialBoundaryPenalty:  lower, upper, strength
ReciprocalBoundaryPenalty:   lower, upper, strength
```

Scalars broadcast. Row arrays are one-dimensional, exact length, defensively
owned/read-only, and strictly validated. Hard intervals are closed and may use
`lower == upper`; soft/boundary penalty width requirements remain unchanged.
Hard applicability is independent of confidence and active membership.
Inapplicable hard rows contribute no feasibility restriction, conflict edge,
violation classification, or hard-induced coupling. Zero penalty strength
remains exact mathematical absence and is removed before dangerous evaluation.

`HuberLoss.delta`, exponential `margin`/`tau`, and reciprocal
`margin`/`epsilon` remain scalar in this first pass. `L2Regularization`
remains a regularizer on weights and does not acquire a separator measurement
space or observation-row strength.

**Binding and compilation semantics**

A vector-valued `FitModel` is unbound positional policy until
`SeparatorFitProblem` construction. Construction binds one resolved owned
policy to one ordered `SeparatorObservations` set. Every component subset,
active subset, final refit, and row re-entry projects observation rows and policy
through the same ordered selection. Length-only association is never sufficient
for an already bound policy; model values do not enter ADR 0014 observation or
source identity.

Each term is transformed through the existing rowwise affine separator/weight
relation. The numerical implementation retains the existing convex scalar
objective/proximal/certificate machinery with row-specific immutable scalar
specifications. Shared compilation/batching is allowed only for identical
complete specifications. Cache keys must include all policy capable of changing
the scalar objective.

**Result and report semantics**

Observation-facing target/prediction/residual fields retain their source-space
meaning. Effective mismatch/model-space views remain explicit. Problem/result
state additionally exposes an inspectable resolved-policy association for its
ordered rows.

Report schema v2 records both effective spaces and the complete
objective-defining resolved model policy: mismatch family/parameters, hard
policy, ordered penalty policy, and regularization strength/reference semantics.
Observation-indexed uniform/scalar values may be represented once;
heterogeneous values are aligned to report row IDs and projected with
observation subsets. Site-indexed regularization references retain site ordering
and are not projected by observation masks. Active reports retain full candidate
policy and their nested fit retains the exact projected selected policy.
Observation identity remains model-independent. Row-oriented `PowerFitBounds`
remain aligned to observations; hard applicability is authoritative for whether
a row carries an effective bound, and absence is never encoded as infinity.

**Acceptance criteria**

- absolute-position mismatch with fractional hard bounds is first-class;
- omitted spaces reproduce v0.8 same-space behavior numerically;
- scalar A+B inputs reproduce the corresponding uniform row vectors;
- independently transformed same-space/mixed-space problems agree with the
  automatic compiler;
- heterogeneous bounded/unrestricted/equality hard rows coexist in one fit;
- hard applicability has true absence semantics in feasibility, conflict,
  violation, coupling, and solver selection;
- row-policy ownership/shape validation rejects wrong length, matrices/columns,
  mutation leakage, and invalid values;
- component and active-set removal/re-entry preserve exact row-policy
  association for duplicate pairs and periodic images;
- two otherwise cache-compatible rows with different policy cannot exchange a
  proximal solution;
- direct/ADMM applicability changes only where actual selected row policy
  requires it;
- reports/results identify observation/model spaces and resolved policy
  unambiguously;
- observation/source identity and fingerprints remain unchanged;
- no C shape parameter, per-row space, generic callback/loss, mixed observation
  block, or chemistry-specific type is added in this pass;
- independent numerical/property oracles cover hard feasibility, scalar
  objective/proximal breakpoints, dense/sparse agreement, and active final-state
  association.

## Issue-scoped implementation and review workflow

The repository's normal issue-scoped implementation contract remains
authoritative. For v0.9, high-risk numerical work adds a stronger review loop
rather than a separate development system.

### 1. Prepare each issue from the current `dev` head

Before implementation, an issue-preparation and review pass reads:

- this active plan;
- the linked issue;
- relevant ADRs and API inventory;
- the actual current source after already accepted work packages.

It re-evaluates the issue-local implementation architecture against current
code, fixes the acceptance contract and independent test oracle, and records
any stop condition. Later implementation details are intentionally not frozen
in advance because preceding accepted changes may make a cleaner implementation
possible.

### 2. One substantial issue per implementation task

The implementation remains limited to the linked issue, including production
code, tests, narrow current documentation/API-inventory/changelog updates, and
reported validation. It must not invent a new public policy or broaden the plan
non-goals.

### 3. Independent adversarial review

A fresh reasoning/review pass reads the complete diff, runs the relevant tests,
uses independent mathematical/property oracles where required, checks hidden API
changes and scope creep, and tries to falsify the claimed invariants.

The review ends with either an explicit acceptance or a finite list of blocking
problems. The next dependent work package should not be built on an unaccepted
foundation.

### 4. Minimal correction loop

When review rejects the implementation, the correction is limited to the
blocking findings. A fresh review follows the correction.

### 5. Maintainer acceptance

Only after independent acceptance does the maintainer treat the work package as
complete and integrate/close it under the normal `dev`/issue workflow.

### Contract-first/high-risk packages

The exact-wrap portion of WP2, certified native-translation portion of WP4,
WP3, WP5, WP6, WP7, and the result/report semantics portion of WP10 require a
contract/test-oracle pass before ordinary production coding begins.

The same contributor may implement a small correctness-critical kernel,
independent test oracle, pathological fixture generator, or narrow schema
normalizer when the contract cannot be cleanly separated from a small
implementation. Acceptance must still come from a separate fresh review rather
than the same review pass that authored the code.

Routine API plumbing, validation, signatures, packaging, ordinary facade code,
and broad regression-test wiring remain implementation work.

## Validation strategy

### Unit tests

Use focused unit tests for:

- exact determinant/dyadic lattice representation;
- exact `U`/`U_inverse` and shift round trips;
- reduction determinism and structural resource limits;
- sign-normalized backend frame construction;
- left-handed improper orthogonal transforms;
- Cartesian/fractional conversion and exact half-open wrapping decisions at
  seams, exact interior remainders whose binary64 view reaches an upper
  endpoint, one ULP to either side, negative coordinates, large shears, and
  left-handed bases;
- unique/ambiguous/inconsistent integer-translation recovery from approximate
  native Cartesian positions;
- whole-problem ghost weight gauge conversion;
- positive-measure boundary eligibility and boundary-reference kind/payload
  validation;
- for WP5, native N source compatibility, exact E/S ideal agreement and
  provenance equivalence; qualify other boundary producers separately;
- initialized 3D native ghost IDs across all standard/power box/periodic routes;
- term-specific separator-space affine compilation;
- report/result space semantics;
- supported realization-aware facade argument normalization.

### Representation metamorphic tests

For a benign row basis `A` and bounded exact integer unimodular matrix `U`, use

```text
A_prime = U @ A
```

and verify that equality in exact dyadic arithmetic before comparing physical
invariants. A rounded matrix product that represents a perturbed lattice is not
a basis-invariance fixture. Corresponding shifts must satisfy

```text
s = s_prime @ U
```

rather than raw shift tuples being equal.

Compare as applicable:

- physical minimum-image displacement and exact distance;
- duplicate classification;
- generator identity;
- cell measures;
- neighbor topology for fixtures with a certified positive margin from
  degeneracy;
- documented ambiguity/normalization behavior rather than raw backend record
  counts for exact or near-degenerate fixtures;
- physical face/edge translations;
- reconstructed owner/query image coordinates.

Include determinant `+1` and `-1` transforms. Different equivalent bases can
produce different wrapped representatives because they define different
fundamental parallelepipeds; tests require each representative to satisfy its
own reconstruction equation rather than requiring raw wrapped coordinates to be
identical.

### Exact-tie tests

Construct deliberate half-cell/symmetry ties and verify:

- the selected physical image is invariant under equivalent user/reduced bases;
- pair reversal negates the selected displacement/shift;
- translating an endpoint by a lattice vector transforms the integer shift
  covariantly;
- exact reduction strategy does not alter the selected physical tie;
- orientation `+1`/`-1` applies the documented smallest/largest exact Cartesian
  tuple rule in fixed caller axes.

### Independent boundary-image oracles

Production reconstruction must not validate itself. Use several independent
checks:

1. independently reconstructed E/S ideal bisectors and classified ideal
   boundaries; audit native vertices separately as rounded observations,
   not exact coplanar ideal vertices;
2. directed reciprocity for persistent cells;
3. explicit small-supercell non-periodic references for selected fixtures;
4. bounded brute-force image enumeration as a test-only oracle;
5. unimodular representation metamorphisms;
6. explicit ghost-insertion references for sparse fixtures;
7. Cartesian reconstruction from user-basis shifts.

A small supercell or bounded coefficient cube is an oracle only when its
coverage is justified independently, for example by a geometric exclusion bound
or a proven stabilization margin. It must not repeat the same finite-window
assumption production is removing.

Ghost-self boundaries normally lack a persistent reciprocal record, so their
oracles emphasize geometry, explicit insertion, and owner-kind/image
reconstruction rather than reciprocity alone. Repeated-process 3D tests cover all
four standard/power box/periodic routes; 2D tests include empty/sparse periodic
negative codes and collapsed edges. Exact coincident cuts with different
provenance and power cases where ideal weights differ detectably from
re-squared backend radii must be included.

### Inverse numerical/property tests

Required independent checks include:

- same-space v0.8 regressions;
- manual relative/absolute separator transformation;
- automatic mixed-space compilation versus an independently manually
  transformed same-space model;
- mixed-space hard infeasibility;
- direct/ADMM agreement where both paths are mathematically applicable;
- unchanged observation/source identity under model-space changes;
- structured active termination and final-layer availability cases.

### Integration qualification

Public integration tests use only public API and cover all workflow families in
WP12. They verify user-visible invariants rather than private algorithm choices.

### Performance/regression boundary

Release gates prefer structural workload counters to absolute timing:

- proof candidate/box size;
- exact candidate count;
- reduction iteration/work count;
- integer bit growth;
- boundary/ghost candidate count.

Private resource limits can yield deterministic success or a structured
resource failure, never an uncertified approximate fallback. Timing benchmarks
may track trends but do not become a fragile release gate. Within qualified
numerical ranges, batched and separate ghost-weight calls should also agree; an
extreme-range backend limitation must become an inspectable failure or narrowly
documented capability boundary rather than unexplained geometry drift.

## Risks and mitigations

| Risk | Consequence | Mitigation |
|---|---|---|
| Exact reduction is mathematically correct but gives little practical proof-work improvement. | Representation robustness remains impractical for the cases that motivate WP3. | Compare algorithms against adversarial candidate/work metrics before production commitment; stop rather than hide another finite radius. |
| Exact integer reduction causes pathological coefficient/bit growth. | Resource blow-up or platform-sensitive behavior. | Track exact structural counters, use Python integers internally, define private deterministic work limits, and fail structurally rather than approximately. |
| Improper backend transform reverses orientation-sensitive geometry. | Vertex winding or signed-normal regressions despite correct distances/measures. | Explicitly audit winding/normals in WP2 and add left-handed metamorphic fixtures. |
| Boundary completeness is asserted from one vertex or a heuristic envelope. | Face/edge shifts can still be wrong outside tests. | For WP5 apply ADR 0021's complete E/S ideal regions and complete producer-route enumeration; qualify the distinct WP6 producer and use independently bounded supercell/test oracles. |
| Rounded inverse/floor controls a half-open wrap under a poor valid basis. | A public integer shift can be wrong while the float point looks plausible. | Decide discrete user wrapping from exact dyadic arithmetic; treat floats only as validated rounded views. |
| Approximate native image coordinates are inverted without certification. | A wrong owner-image translation can be selected near a lattice boundary. | WP4 requires uniqueness within its justified exact compatibility box; WP5 uses ADR 0021's complete producer attribution. Ambiguity fails structurally. |
| Native polygon area is treated as exact semantic measure. | Positive native faces may correspond to exact zero or strictly absent ideal boundaries. | For WP5 reconstruct exact E and S independently when diagnostics are requested; report mismatches through `tessellation_check` while preserving uniquely source-attributed shifts, per ADR 0021. |
| Ideal input weights are used as the native power-plane arithmetic oracle. | Certification can disagree with the radii/arithmetic Voro++ actually consumed. | For WP5 attribute actual N planes from qualified binary64 source operations; reconstruct native-effective E and public-semantic S separately, per ADR 0021. |
| Native ghost neighbor IDs are treated as reliable when they are not. | Ghost self-images can be mislabeled as generators/walls or expose indeterminate IDs. | Require a 3D native-bridge correction that prevents the read, then apply tagged semantic reconstruction; prefer a clean binding-only fix, and if vendored source is required, reduce it to a minimum concrete diff and settle D9 from that evidence before acceptance. |
| Ghost schema redesign spills into unnecessary ordinary-result churn. | Large avoidable breaking surface. | Require semantic normalization internally; change ordinary `compute()` result fields only where correctness or coherent public contract demands it. |
| Mixed separator spaces accidentally change observation identity or old result semantics. | Stored/reproducibility contracts break for reasons unrelated to the scientific model. | Keep observation measurement/source identity fixed, add explicit mismatch/model views, and version strict reports if their schema changes. |
| Realization-aware promotion freezes research/path internals. | 1.0 carries knobs that are difficult to support scientifically. | Keep the high-level facade small; leave hysteresis/path controls in the advanced namespace unless an issue proves a stable downstream need. |
| Poor but valid lattice is accepted by the constructor but Voro++ cannot resolve it. | Users may interpret later failure as a regression. | Separate mathematical validity, backend representability, and certified-resource failure in diagnostics and qualification wording. |
| Extreme power-weight native behavior varies by compiler/platform. | Brittle regression tests or false promise of a universal safety threshold. | Test a behavior envelope: structured failure or finite/consistent geometry; do not assert corrupted geometry or a guessed cutoff. |
| v0.9 becomes a general cleanup/refactor release. | Scope and review become unbounded before 1.0. | Enforce issue-local non-goals, checkpoints, and final API audit; defer cosmetic and unrelated architecture work. |

   search window and cover standard/power, supported partial/full periodicity,
   and self-neighbor cases.

   unresolved attribution fails atomically. Requested exact-consistency

    own producer routes.
11. Periodic ghost boundaries reliably distinguish persistent generators,
    ghost self-images, and walls, including sparse/empty periodic fixtures.
12. No uninitialized 3D temporary ghost ID is read on any supported
    standard/power box/periodic route; internal seed values are not public
    semantic authority.
13. Query, owner, and ghost metadata obey documented reconstruction equations,
    define `p_ghost_site` as the active cell-site representative, and do not
    conflate original input, user wrapping, backend-primary, or native internal
    coordinates.

    forced into public results when the user did not request them.

    reconstruction-only tolerance controls are removed, and `ghost_radius` is
    removed without a deprecated alias.

    spaces preserve v0.8 same-space behavior.
17. The accepted A+B whitelist supports scalar-broadcast or row-wise hard

    binding, subsetting, coupling, active re-entry, and report association;
    observation/source identity remains unchanged.

    `pyvoro2.inverse` without requiring ordinary callers to use the advanced
    separator namespace.
19. Outer active-set non-success outcomes remain structured and distinct from
    final inner-fit status; coherent final states are not discarded merely
    because the outer loop cycles or reaches its iteration limit.
20. Canonical public workflows require no private imports, manual
    weight-to-radius conversion, manual handedness repair, custom minimum-image
    code, manual shift recovery, correctness-window tuning, or experimental
    active namespace.
21. Representation, exact-tie, boundary-image, ghost, and mixed-space tests use
    independently justified metamorphic or explicit oracles rather than only
    production self-comparison or another unexplained finite search window.
22. The extreme power-weight/Voro++ resolution limitation has a platform-robust

    fabricated universal cutoff.

25. No known critical correctness or semantic hole remains in the
